## What it does

A specification (v0.2) from Google Cloud Platform for representing knowledge as a directory of Markdown files with YAML frontmatter — designed to be authored by people, generated by agents, exchanged across organizations, and consumed by both. A "Knowledge Bundle" is a directory tree of `.md` files where each file is a "Concept" with a required `type` field in frontmatter. The spec defines: concept documents (frontmatter + body), cross-linking via standard Markdown links, index files for progressive disclosure, log files for change history, and citations for external sources.

Key v0.2 additions over v0.1:
- **Provenance**: `sources` with per-source credibility signals, `generated` and `verified` metadata
- **Freshness**: `status` and `stale_after` frontmatter fields for currency tracking
- **Trust tiers**: Consumers can derive trust from provenance signals without bespoke runtime

The repo ships a reference agent (BigQuery metadata + LLM-driven web crawler) that produces OKF bundles, and a self-contained interactive HTML visualizer (Cytoscape.js graph + markdown rendering) that consumes them. Four sample bundles: GA4 e-commerce, Stack Overflow, Bitcoin, Acme Retail.

Design principles: readable without tooling, parseable without SDKs, diffable in git, portable across tools. Deliberately minimal — only standardizes `type` as required; everything else is optional. Consumers must tolerate unknown types, unknown frontmatter keys, and broken links.

## Assessment

The spec remains closely aligned with our kb wiki patterns (Markdown + YAML frontmatter, cross-linking, index generation, hierarchical organization). v0.2's provenance and freshness signals are the meaningful addition — they formalize trust metadata we handle informally. Still note rather than adopt because: (1) our existing wiki format is more feature-rich (search indexes, wikilinks, categories), (2) the spec adds no capabilities we don't already have beyond the trust/provenance formalization, (3) the primary value would be cross-organization knowledge exchange. The reference agent's two-pass architecture (structured metadata → LLM web enrichment) is a useful pattern reference. The visualizer demonstrates OKF as a consumption target.

## Mechanical details

- A bundle = directory tree of `.md` files (git repo recommended for distribution)
- Required frontmatter: `type` (e.g., "BigQuery Table", "Playbook", "Metric")
- Recommended frontmatter: `title`, `description`, `resource` (URI), `tags`, `timestamp`
- v0.2 frontmatter: `sources` (with credibility), `generated`, `verified`, `status`, `stale_after`
- Reserved filenames: `index.md` (directory listing), `log.md` (change history)
- Cross-linking: absolute (bundle-relative) or relative markdown links
- Citations: numbered external sources under `# Citations` heading
- Conformance: parseable YAML frontmatter + non-empty `type` = conformant
- Reference agent: `python -m reference_agent enrich --source bq --dataset <project>.<dataset> --out ./bundles/<name>`
- Visualizer: `python -m reference_agent visualize --bundle ./bundles/<name>` → self-contained HTML
- Install: `pip install -e .[dev]` (Python 3.13+)
