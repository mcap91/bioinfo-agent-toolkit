## What it does

A framework for recursive self-improvement that targets the *process* an agent uses rather than just refining its final answers. A single, fixed "universal meta-operation" Ω reads execution traces (commands, errors, reasoning, success/score) from the layer(s) beneath it and writes new executable code — a `pre_process` hook plus a `code_library` dict of helper functions — that gets injected into the layer below, changing its behavior. Applying Ω repeatedly builds a stack of meta-layers whose roles emerge from context rather than being hand-designed; unlike prior self-improvement systems that are purely evaluative (accept/reject a change), these meta-layers are constructive — they write code.

**Stack architecture:** Layer 0 (`BaseExecutor`) runs candidate scripts locally or in a Docker sandbox and records a `Trace`; Layer 1 is a default solver (an LLM agent, either a single-pass `Layer1Solver` or an iterative `AgenticSolver`); Layer 2+ are emergent, generated by Ω from the traces of the layers below. Search alternates a build step (Ω writes a new meta-layer from current traces) and a run step (the full nested stack executes on each task). A worked example from the paper: on a LawBench charge-prediction lineage, Ω injects a fuzzy label matcher, a later over-aggressive prompt change regresses the score, and the next layer rolls that back and standardizes on the verified helper — raising the score from 0.767 to 0.833.

**Orchestration:** search is driven by an archive-based `EvolutionaryOrchestrator` (the only orchestrator) — a monotonically growing archive of evaluated candidate chains, tracking per-task bests and supporting weighted parent selection; `--use-archive` is required to run it. `--benchmark-config none --use-archive --max-iterations 0` reproduces bare best-of-N behavior as a control.

**Benchmarks (9, via `--benchmark`):** CO-Bench (combinatorial optimization, 36 tasks), Symptom2Disease (22-class medical diagnosis), LawBench charge prediction (Chinese, multi-label F1), TerminalBench 2.0 (~113 tasks, via harbor), SWE-bench Verified (500 GitHub issues, % resolved), AlphaEvolve Math, Symbolic Regression, and AlgoTune (all OpenEvolve-family), and ARC-AGI-2 (120 eval tasks, pass@2). Datasets are not bundled — fetched per `data/README.md` instructions per benchmark.

**Install/run:** Python ≥3.11 (CI: 3.11/3.12), `pip install -e .` plus optional extras (`dev`, `bench`, `classify`, `analysis`, `harbor`, `openevolve[-jax]`, `terminus2`/`openhands` external-agent SDKs). API keys via `.env` (OpenRouter or Azure OpenAI). External base solvers (`--base-solver openhands|terminus2`) run in a separate venv as child-process runners with a cost guard, bounded Docker-lease guard, and JSONL telemetry ledger; `--daily-budget-usd` is required for them.

**Author's own status framing:** explicitly called a research prototype; its demonstrable properties are a monotone archive (behaves as a ≥best-of-N order statistic) and a working code-injection channel, with results described as exploratory and "should not be read as headline wins."

## Security

MIT, open source. Runs candidate code (its own and LLM-generated helper functions) via a `BaseExecutor` that supports Docker sandboxing — local (non-sandboxed) execution of LLM-written code is also supported and is the higher-risk configuration. External-agent backends add an explicit cost guard and a bounded Docker-lease guard, suggesting the authors anticipated runaway-cost and resource-exhaustion failure modes from autonomous, budget-driven runs. On-disk artifact formats are pinned by golden tests, which limits (but doesn't eliminate) silent format drift as an operational risk. No independent security audit found; research-prototype status per the authors' own README.
