## What it does

The MCP 2026-07-28 specification is the largest update to the Model Context Protocol since its initial release. Informally called "v2" by the community, it finalizes MCP's transition to a fully stateless architecture, hardens the authentication model, establishes a formal 12-month deprecation policy, and graduates two capabilities — interactive server-rendered interfaces (UI) and long-running asynchronous tasks — into official protocol extensions.

Key changes:

- **Fully stateless architecture**: Removes the requirement for persistent sessions between MCP clients and specific server instances. Under the old design, if the server holding session state disappeared, the agent's work disappeared with it. The new model lets organizations run MCP servers behind standard load balancers using existing Kubernetes and cloud-native DevOps tooling.
- **Hardened authentication**: Strengthens OAuth and OIDC authorization, addressing a known class of attacks against the prior auth model.
- **Deprecation policy**: Formal 12-month deprecation window for protocol changes, giving implementors stability guarantees.
- **Graduated extensions**: Server-rendered UIs and async tasks (long-running operations) move from experimental to official extensions.

The update is stewarded by the Agentic AI Foundation (AAIF), a directed fund under the Linux Foundation. AAIF has grown from ~40 members at its December inauguration to 240, with SDK downloads doubling in six months to ~250 million per week. The publicly released MCP tool ecosystem grew from ~5,000 to 177,000 tools over the past year.

## Assessment

Critical reference for understanding the current MCP landscape. The stateless architecture change directly affects deployment decisions for any MCP server (including the catalog MCP server in this project). The authentication hardening is relevant to any MCP server handling sensitive data. The 12-month deprecation policy provides a stability signal that was previously missing.

## Security

The spec hardens MCP's auth model with stronger OAuth/OIDC requirements. No specific security flags — this is a protocol specification, not executable code.
