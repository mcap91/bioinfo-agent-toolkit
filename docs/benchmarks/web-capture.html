Headless browser capture: a three-engine comparison

2026-10-26

Summary

This note asks which headless-browser engine an agent-tool catalog should reuse for pages that need a real browser to capture. Three engines (a custom Playwright script, crawl4ai, and playwright-cli) were run on the same corpus: 18 Reddit share links plus 4 non-Reddit pages. All three resolved every share link and captured every post title and body; they differed on comment-section capture (crawl4ai 15/18), on non-Reddit pages with an unchanged configuration (crawl4ai 0/4), median wall time (1.94–11.87 s per page) and median tokens per page (5,574–11,416). The custom Playwright script was selected: it captured every comment section and non-Reddit page, as playwright-cli did, at a median 3.72 s per page against 11.87 s, and used about half of crawl4ai's tokens (5,652 against 11,416).

Engines and configurations

Each engine ran with one fixed configuration for every page. Excerpts below are copied from the files that ran.

Custom script — Playwright 1.64.1 (Python)

Headless Chromium with a Chrome user agent. Polls for the post element (shreddit-post), then saves document.body.innerText.

uv run --project own python own/capture.py <url> 1 <out_path>
ctx = b.new_context(user_agent="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/141.0.0.0 Safari/537.36", viewport={"width":1280,"height":900})
n = 0
for i in range(10):
    time.sleep(2)
    n = pg.evaluate("document.querySelectorAll('shreddit-post').length")
    if n: break
comments = pg.evaluate("document.querySelectorAll('shreddit-comment').length")

crawl4ai — crawl4ai 0.9.5

Library mode. Playwright underneath, with built-in HTML-to-markdown conversion and a wait_for CSS selector in place of a polling loop. The counted output is raw_markdown.

CRAWL4AI_NO_CLOUD_NOTICE=1 uv run --project crawl4ai python crawl4ai/capture.py <url> <out_path>
browser_cfg = BrowserConfig(headless=True, user_agent=CHROME_UA)
run_cfg = CrawlerRunConfig(
    wait_for="css:shreddit-post",
    wait_for_timeout=20000,
    page_timeout=45000,
    markdown_generator=DefaultMarkdownGenerator(content_filter=PruningContentFilter()),
)

playwright-cli — @playwright/cli 0.1.22

The CLI has no text-dump command and no wait-for-selector command; both are implemented with eval calls. A custom user agent can be set only through a configuration file.

node pwcli/capture.mjs <url> <out_path>
playwright-cli --config pwcli/.playwright/cli.config.json open <url>
playwright-cli eval "async () => { let n = 0; for (let i = 0; i < 10; i++) { await new Promise(r => setTimeout(r, 2000)); n = document.querySelectorAll('shreddit-post').length; if (n) break; } return n; }" --raw
playwright-cli eval "() => ({url: location.href, title: document.title, posts: document.querySelectorAll('shreddit-post').length, comments: document.querySelectorAll('shreddit-comment').length})" --raw
playwright-cli eval "() => document.body ? document.body.innerText : ''" --raw --filename <tmp.json>
playwright-cli close

Method

Corpus. 18 Reddit share links (reddit.com/r/<sub>/s/<id>) saved for later review; a plain HTTP fetch cannot resolve them. 2 of the links point to a specific comment. Three non-Reddit pages tested configuration reuse: a static product page, a JS-heavy GitHub repository page, and an Instagram reel behind a login prompt. A JS-rendered pricing page, run as a probe (below), is counted as the fourth non-Reddit page.

Runs. Each Reddit link was loaded twice per engine, back to back (first and repeat); all reported results use the first run. Non-Reddit pages ran once. Engines ran sequentially, never in parallel, with a fixed 5-second delay between page loads.

Capture checks. Each check scored 1 or 0 per capture.

  • Share link resolved: the final URL matches the post pattern /r/<sub>/comments/<id>/.
  • Title and body: the captured title equals the custom script's first-run title for that link, and the captured content is at least 500 characters. Non-Reddit pages have no reference title, so they pass with a non-empty title and at least 500 characters.
  • Targeted comment (2 links only): the first 100 characters of the comment's text, whitespace-normalized and taken from an independent reference load of the page, appear in the capture.
  • Comment section: the capture contains the marker "Comments Section" or "Sort by" (case-insensitive), the interface text Reddit renders around the comment list.

Tokens. Each capture was sent through claude --print --output-format json on a Claude subscription, model claude-sonnet-5, with a fixed one-word-reply instruction. The input-side token total of that call minus the total for the same instruction with empty text (baseline 8,653 tokens) is the capture's token count. The 60 counting calls cost about $1.89 at list price.

Install footprint. Package counts come from each engine's lockfile. Environment size is du -sh of the Python virtual environment or node_modules. The browser download is the size of the Chromium, headless shell, and ffmpeg builds each engine pins, measured in the Playwright browser cache.

Out-of-corpus probes

Two further pages were captured once with each engine's unchanged configuration.

  • JS-rendered pricing page (deepinfra.com/gpu-instances): the custom script captured 3,154 characters and playwright-cli 3,153, both including the GPU price rows (for example $4.89/hour) after a cookie banner and navigation. crawl4ai returned no content: Timeout after 20000ms waiting for selector 'shreddit-post'.
  • PDF (arxiv.org/pdf/1706.03762): every engine received a file download instead of a rendered page. The custom script raised Page.goto: Download is starting and exited with status 1, writing no output. crawl4ai hit the same error, caught it, and returned an empty capture. playwright-cli returned an empty capture with no error. PDFs were outside the scope of this comparison.

Limitations

  • The pass rule for non-Reddit pages (non-empty title and at least 500 characters) is weak and cannot distinguish a correct page from a loaded but wrong one.
  • The Instagram page tests configuration reuse only, not Instagram capture: it passed with the title "Instagram" on a login prompt, although the reel caption appeared in the captured text.
  • Non-Reddit pages ran once, so they carry no repeat measurement.
  • An earlier version of the targeted-comment check searched for the comment ID, which appears only in link targets and never in page text; it was replaced by a match against independently captured reference text.
  • No qualitative scoring of clutter or output usability was performed.

Selected engine and rationale

The custom script, built on Playwright 1.64.1 (Python), was selected. The choice rests on these measured results: comment section 18/18 (crawl4ai 15/18); 4/4 non-Reddit pages captured with an unchanged configuration (crawl4ai 0/4); median 5,652 tokens per page (crawl4ai 11,416); 5 packages and 142 MB (crawl4ai 98 packages and 703 MB); median 3.72 s per page (playwright-cli 11.87 s). On a PDF it fails with an explicit error that can be caught, so PDFs can be routed to a document-conversion pipeline instead of the browser. It is used as one shared script with a per-site wait condition (by default a short fixed wait), not a separate script per site.
